# 斷點：AI 長頸鹿任務續接夥伴

> 使用 AMB82-mini 與 Android 裝置端 AI，協助大學生在離席返回後接回最後一次記下的工作進度。

## 一、研究動機與問題

大學生讀書、寫報告或進行專題時，可能因為接電話、拿資料或處理臨時事情而離開座位。回來之後，即使知道原本在做什麼，仍可能需要重新翻找資料，回想「剛剛做到哪裡」和「接下來要做哪一步」。本專題將這個情境稱為「任務斷點」。

我們提出桌面長頸鹿玩偶「斷點」。使用者透過實體按鍵口述任務，手機將內容整理成簡短紀錄；玩偶在板端觀察指定座位區是否有人，於離席返回後提供提示。設計希望降低重新開始工作的負擔，實際效果則透過後續使用測試評估，不預設產品必然提升效率。

## 二、使用對象與設計目標

主要使用對象為在固定書桌讀書、寫作或製作報告的大學生。使用情境限定單人、固定座位及一次一項進行中任務，手機與玩偶連上同一區域網路，展示時手機 App 保持前景執行。

本專題的目標為：

1. 讓使用者用一句話留下任務、目前進度與下一步，不必操作複雜表單。
2. 利用 MCU 的現場感測，在使用者回座後提供適時的續接入口。
3. 提示前先取得使用者確認，避免剛回座便自動播報而造成干擾。
4. 保留最後一次確認的斷點，讓辨識、連線或模型失敗不致覆蓋原紀錄。

## 三、創新構想與核心價值

「斷點」將 **口述保存斷點、實體在席感知、確認後續接** 結合成一個工作流程。相較於以固定時間提醒休息的計時器，本設計由離席與返回事件觸發提示；相較於一般聊天玩偶，互動圍繞一項具體任務與可保存的進度；相較於手動備忘錄，玩偶提供現場感測、實體按鍵及燈號，形成桌面上的續接入口。

本提案的差異在於互動機制及使用情境，不以「全球首創」作為主張。AI 的角色是整理使用者提供的資訊，將斷點轉成容易理解的提示；任務保存、確認、計時與觸發條件由程式控制。

## 四、操作情境

### 情境：從報告研究動機接續文獻搜尋

1. 學生按住玩偶按鍵說：「我要寫報告，目前整理到研究動機，下一步找兩篇文獻。」
2. 玩偶錄音後，手機將內容整理為「任務：寫報告／進度：研究動機／下一步：找兩篇文獻」，透過玩偶喇叭讀回。
3. 學生短按確認，手機才將草稿存為正式斷點。聽錯時可重新按住說話，取代草稿。
4. 學生離席拿資料。MCU 判定座位區持續無人後，標記離席；不推測離席原因，也不修改工作進度。
5. 學生回座，玩偶亮起續接提示燈。學生短按後，玩偶才說：「上次記下的是研究動機，下一步是找兩篇文獻。」
6. 工作推進後，學生可再次口述更新；結束時說「任務完成」，經讀回及短按確認後，停止該任務的回座提示。

若學生突然離席、來不及更新，系統只能提示最後一次確認的紀錄。若尚未留下斷點，系統不生成虛構進度，而是提示先建立紀錄。

## 五、系統架構與技術依據

```text
使用者按鍵口述
      ↓
AMB82-mini：錄音、板端座位人形偵測、事件計時
      ⇅ 同一區網：錄音／事件 → 手機；燈號／播放音訊 → 玩偶
Android 專題 App：LiteRT-LM／Gemma 4 E2B、確認流程、任務保存、TTS
      ↓
玩偶讀回 → 使用者短按確認 → 保存斷點
      ↓
離席後返回 → 玩偶先亮燈 → 短按後讀出最後確認的下一步
```

| 部分 | 本專題規劃的工作 |
|---|---|
| AMB82-mini | 攝影機取得畫面、板端人形偵測、座位區判定、事件計時、按鍵錄音、燈號與音訊播放 |
| Android 專題 App | 區網通訊、下載錄音、音訊格式轉換、任務資料保存、確認流程、模型呼叫與語音合成 |
| Gemma 4 E2B／LiteRT-LM | 錄音轉文字、從口述整理任務資訊、依已確認紀錄產生簡短提示 |

AMB82-mini 的官方物件偵測範例提供物件種類、位置框與信心分數，可作為人形與座位區判定的基礎。官方亦有按鍵錄音、將音訊送往外部服務的範例。這些範例證明可採用的技術途徑，並不代表本專題的整合流程已由範例提供。[1][2]

手機端採 LiteRT-LM 開發專題 App，使用 Gemma 4 E2B 的音訊與文字能力。AI Edge Gallery 作為先行驗證模型與手機效能的工具；原版 Gallery 不直接等同具備本專題所需的 MCU 通訊、任務保存或回座觸發流程。[3][4][5]

### 通訊與資料流

手機 App 主動向 MCU 輪詢事件；遇到錄音就緒事件時，下載短音檔，解碼並轉成單聲道、16 kHz、16-bit PCM／WAV，再交由模型轉錄與整理。App 透過 Android TTS 產生音訊，初始規劃轉為 16 kHz、16-bit、單聲道 PCM 後回送玩偶。格式轉換、傳輸與板端播放需自行開發，並在音訊里程碑驗證，不能視為安裝 App 即有的功能。錄音與播放採分時方式，避免玩偶將自己的聲音當成輸入。

MCU 介面需提供事件讀取、錄音取得、確認回覆、燈號設定及播放音訊等功能。事件帶有序號，草稿帶有識別碼，讓重試及重複按鍵不致重複保存或確認到過期草稿。這些介面屬本專題的開發內容。

## 六、感測與互動規則

### 座位區判定

攝影機朝向預先設定的座位區，依 person 偵測框的位置與信心分數判定有人／無人。初始參數規劃為信心門檻 0.6、有效觀測中連續無人 15 秒才標記離席、連續有人 3 秒才標記回座；以上均為可校準的設計起點，不是實測性能。

辨識僅回答指定區域是否有人，不辨識使用者身分，不判定專心程度。短暫彎腰、遮蔽、路人及光線不足均須列入測試。只有有效推論影格參與計時；錄音、播放或傳輸期間可暫停視覺處理以降低資源衝突，暫停、掉幀與失聯不得當成無人時間累加。啟動、重連或恢復視覺處理後，先重建穩定基準；活動任務期間觀察到在座、離席、返回的完整轉換，才觸發續接提示。

### 按鍵與確認

| 狀態 | 操作與回應 |
|---|---|
| 記錄任務／進度 | 按住達 0.5 秒開始錄音，放開停止；最長 20 秒，達上限自動停止，同一次長按不觸發短按 |
| 待確認草稿 | 讀回後短按儲存；再次按住則重新錄製，取代舊草稿 |
| 回座待續接 | 先以燈號提示，短按才播放最後確認的斷點 |
| 一般任務期間 | 短按可重播最後紀錄；按住可更新 |
| 完成任務 | 口述完成意圖後讀回，短按確認才結束 |

同一時間只保留一份待確認草稿。讀回結束後 30 秒未確認即取消，原正式紀錄不變；處理或播放中不接受新的錄音或確認，重複按鍵不加入佇列。模型不得自行補入已完成工作、文獻名稱或使用者未說明的下一步；缺少必要資訊時先請使用者補充。

## 七、硬體與電路規劃

| 材料 | 數量 | 用途 |
|---|---:|---|
| AMB82-mini，含相容攝影機及板載麥克風 | 1 | 人形偵測、錄音與控制 |
| Android 手機 | 1 | 本地模型、資料保存與語音合成 |
| 瞬時按鍵 | 1 | 錄音、確認及播放操作 |
| 共陰極 RGB LED 及 1 kΩ 電阻 ×3 | 1 組 | 顯示錄音、處理、待確認、續接及錯誤狀態 |
| PAM8403 音訊放大模組與相容小型喇叭 | 1 組 | 播放讀回與續接提示 |
| microSD 卡 | 1 | 暫存短音訊及固定提示音 |
| USB 5 V 電源、線材與固定結構 | 1 組 | 穩定供電與電子零件固定 |
| 長頸鹿玩偶外殼 | 1 | 桌面互動外型，保留鏡頭與收音／出聲開口 |

按鍵使用 D4／PF11 與 GND，啟用內部上拉；RGB 的 R／G／B 分別由 D5／PF12、D6／PF13、D7／PF14 各串 1 kΩ 驅動，共陰極接 GND。上述 D4 等為 Arduino 數位編號，不是排針實體位置。

板端 AOUT 經 AC 耦合接 PAM8403 IN_L；若所選模組已有輸入耦合電容，不重複加裝。USB 5V 分成板端 Micro USB 與功放兩條供電支路並共地，不從 GPIO 或板端 3.3V 供應功放。喇叭只跨接功放 L+／L−，BTL 輸出兩端都不接地，也不併接左右聲道。實際板件版本及功放模組需依官方圖及模組原理圖核對，腳位、Micro USB 供電及功放輸入／輸出的依據見參考資料 [8]–[10]。

電子模組置於可拆卸固定內架並保留散熱空間；本設計不加入輪子、伺服馬達或電池充電電路。

## 八、資料保存與失敗處理

正式紀錄保存於手機，只長期保留使用者確認的口述文字、任務、目前進度、下一步、確認時間及任務狀態；儲存成功前不覆蓋舊紀錄。模型摘要不清楚、收音失敗或連線中斷時，保留最後確認版本並以燈號提示重試。沒有可靠連線時不承諾完成新的語音記錄或續接播放。

鏡頭影像僅供板端人形偵測，不傳送或保存。麥克風只在按鍵錄音時啟用，並顯示錄音燈。確認、取消或草稿 30 秒逾時後，刪除兩端原始錄音與讀回暫存；尚未傳輸完成的錄音最多保留 60 秒，逾時清除並提示重錄。未確認文字不加入長期紀錄，正式文字可由手機刪除。模型與語音資源下載後，以本地處理為設計目標，仍須保有手機與 MCU 的區網連線。

## 九、預定開發階段與分工

| 階段 | 工作與階段檢核 |
|---|---|
| 1. 技術驗證 | 確認目標手機能執行模型、中文短錄音可轉錄及 TTS 可用；分別測試人形偵測、按鍵與喇叭 |
| 2. 板端整合 | 建立座位區、離席／回座規則、錄音與音訊播放；確認處理暫停不造成假離席 |
| 3. 手機與通訊 | 建立事件讀取、音訊傳輸、草稿確認與本地資料保存；測試重試及版本一致性 |
| 4. 情境展示 | 整合長頸鹿外殼，校準感測位置，依測試計畫記錄結果與修正 |

三人小組可分為板端與電路、手機與 AI、互動設計與整合測試；兩人小組則由一人負責板端，一人負責手機，兩人共同進行外型、文件與測試。具體工作量依組員專長調整。

## 十、風險與因應

| 風險 | 因應方式 |
|---|---|
| 手機模型記憶體、載入或延遲問題 | 先以官方工具實測；8 GB 記憶體級手機僅作選機起點，不保證效能，記錄實機與模型版本 |
| 中文辨識錯誤或摘要補寫資訊 | 使用短句與讀回確認，保留原紀錄，分開檢查轉錄與摘要品質 |
| 玩偶音訊傳輸、解碼及 TTS 播放不相容 | 先打通單次短錄音到單次播放，再整合任務流程；避免同時錄放音 |
| 遮蔽、低光或他人進入座位區 | 固定鏡頭、校準區域與持續時間，必要時由使用者停用自動提示；不宣稱身分辨識 |
| Wi-Fi 斷線、重送或手機 App 被切到背景 | 展示時前景執行；利用事件序號與草稿識別碼避免重複操作，連線失敗不覆寫 |
| 突然中斷前沒有更新進度 | 明確提示「最後一次記下的內容」，不將舊紀錄說成即時工作狀態 |

## 十一、驗證方法與預期產出

以下為預定驗證方法，門檻與數值均為設計起點，不作為測試成果。技術測試需記錄成功次數、失敗情境與各階段耗時，避免只展示單一成功案例。

| 測試類別 | 測試內容與判準 |
|---|---|
| 感測 | 重複離席回座、短暫彎腰、路人經過及低光情境；統計誤觸發、漏判與提示延遲 |
| 任務記憶 | 新增、更新、完成、草稿逾時及突然離席；核對只有確認動作會改變正式紀錄 |
| 語音 | 不同中文表達及適度背景噪音；檢查轉錄、三項摘要欄位及玩偶播放可理解程度 |
| 通訊 | 處理中斷線、重連、重複按鍵與過期確認；核對不遺失舊紀錄、不重複保存 |
| 使用價值 | 邀請約 5 位同學，以兩項相近報告任務比較無輔助與有斷點提示的續接耗時與主觀感受，交錯條件順序 |

使用測試屬小規模可行性觀察，需記錄口述所花時間，連同續接時間評估整體負擔；結果不足以推論所有學生都有效。預期產出為可重複展示的續接流程、技術測試紀錄與使用回饋，據此評估是否值得延伸至多任務或其他情境。
